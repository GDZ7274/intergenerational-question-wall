# 双向问答便利贴墙 MVP PRD

- 版本：0.1
- 状态：可进入低保真原型
- 产品形态：持续运营、移动端优先的 Web/H5 产品；桌面端提供兼容浏览

## 1. 产品定义

一个让大人和小朋友持续互相提问、回答和阅读的线上问答墙。公开问答以便利贴形式展示，保留线下活动轻松、低压力和偶遇式阅读的体验。

产品不是单场活动页，也不是强调用户关系的社交社区。核心是持续产生、完成并传播“跨身份问答”。

## 2. 产品目标

### 2.1 用户目标

- 浏览者可以不登录、不选择身份，直接阅读各种问答。
- 提问者可以快速把问题交给另一身份，并在收到回答后回来查看。
- 回答者可以从适合当前身份的问题池中选择愿意回答的问题。
- 用户可以通过文字和便签样式感受到真实、轻松的交流氛围。

### 2.2 运营目标

- 持续保持“大人问小朋友”和“小朋友问大人”两个方向的内容供给。
- 提高问题在合理时间内获得第一条有效回答的比例。
- 通过精选和预置内容解决冷启动与内容断档。
- 在涉及未成年人的前提下，确保公开内容可控、可追溯、可撤下。

### 2.3 MVP 非目标

- 不做私信、加好友、用户关系链或公开联系方式。
- 不做自由评论区、儿童回答排行榜或竞争性积分。
- 不做图片、语音、视频、手写画布和 AI 代答。
- 不做单场活动报名、签到或票务功能。

## 3. 用户与权限

| 用户类型 | 是否需要身份 | 主要能力 |
| --- | --- | --- |
| 游客 | 否 | 浏览推荐问答墙、查看详情、分享、举报 |
| 参与者 | 大人或小朋友 | 提问、回答、查看自己的内容与通知 |
| 运营人员 | 后台账号 | 审核、精选、置顶、预置内容、数据查看 |
| 管理员 | 后台账号 | 用户处置、权限管理、审计、全站开关与数据删除 |

前台可以使用化名或匿名展示，但正式版本必须在后台保留稳定、可追溯的用户或会话标识。身份是内容参与角色，不等同于公开展示真实年龄。

## 4. 核心规则

### 4.1 身份与动作矩阵

| 当前身份 | 提问 | 回答 |
| --- | --- | --- |
| 大人 | 向小朋友发布问题 | 回答小朋友提出的问题 |
| 小朋友 | 向大人发布问题 | 回答大人提出的问题 |

用户不再手动选择“大人问小朋友答”或“小朋友问大人答”。方向由身份和动作自动推导，服务端必须再次校验。

### 4.2 浏览规则

- 根路径先显示沉浸式参与入口，游客可以直接下滑进入公共问答墙，全程无需选择身份。
- 只展示审核通过且未隐藏的内容。
- 默认进入单张推荐流，不要求游客理解或选择问答分类。
- 使用近期已看记录排除重复推荐；当前内容耗尽后不自动循环。
- 游客点击“提问”或“回答”时，才进入身份选择。
- 详情页展示一个问题及其全部已发布回答；墙面将每个“问题 + 回答”投影成一张便签。

### 4.3 内容规则

- 问题与回答分开发布和审核。
- 一道问题允许多个回答，MVP 默认上限为 20 条，可由后台配置。
- 提问者可以关闭继续回答，但不能删除其他用户已发布的回答。
- 官方预置内容前台不显示来源标签，与用户内容自然混排。
- 后台必须保留 `source=official|user`，用于运营统计、审计和处置。
- 预置内容和用户内容遵循相同的公开审核、隐藏及删除规则。

### 4.4 安全规则

- 不采集或公开真实姓名、学校、住址、电话、定位等非必要信息。
- 输入过程中持续提示不要填写个人敏感信息。
- 不开放私信、加好友、外链推广和线下联系功能。
- 所有公开问题与回答必须经过审核；自动检测只作为人工审核辅助。
- 支持举报、撤回、隐藏、封禁及审计记录。
- 高风险内容需有升级处理规则，至少覆盖欺凌、自伤、性暗示、诱导联系与联系方式泄露。

## 5. 信息架构

移动端主导航固定为三项：

1. 问答墙：公共浏览入口。
2. 参与：选择提问或回答；未选择身份时先补选身份。
3. 我的：我的提问、我的回答、草稿、通知、收藏与身份切换。

桌面端使用顶部导航，保持相同信息结构，但不作为首轮交互设计和验收重点。

## 6. 核心用户故事

### 6.1 游客自由浏览

作为游客，我希望打开页面后直接看到真实问答，不必先注册或选择身份，以便判断内容是否值得继续参与。

验收要点：

- 首屏可见已发布便签和“先逛逛”语义。
- 默认连续推荐，页面不出现内容分类或排序筛选。
- 上滑进入下一张未看便签，下滑回看本次会话历史。
- 刷新和再次进入不会立即推荐已经看过的便签。
- 浏览过程中不强制弹出身份选择或登录。
- 尝试提问或回答时才进入身份选择。

### 6.2 大人提问

作为大人，我希望发布一个给小朋友的问题，并在收到回答时获得通知。

验收要点：

- 目标身份自动显示为“小朋友”，不可手动改成大人。
- 提交后状态清晰显示为审核中、待回答、已有回答或已关闭。
- 审核通过后进入小朋友待回答池。

### 6.3 小朋友回答

作为小朋友，我希望看到大人提出的问题，并直接在完整便利贴中写下回答。

验收要点：

- 问题池只返回目标身份为小朋友的已审核开放问题。
- 回答提交后显示审核状态，不会立即公开未经审核的内容。
- 审核通过后形成公开问答便签，并通知原提问者。

其他两条路径按同样规则对称实现。

## 7. 功能需求

### 7.1 问答墙

- 展示已完成问答卡片，卡片明确标注“谁问、谁答”。
- 默认按运营精选、内容质量与时效组合推荐，不暴露排序控件。
- 持久化近期已看记录，自动推荐只从未看内容中选择。
- 手机端固定视口一次展示一张便签，支持上滑下一张、下滑回看。
- 支持打开详情、分享、收藏和举报。
- 首屏先展示内容，不使用营销型大幅介绍区。
- 浏览页背景由密集便签墙与高模糊毛玻璃构成，前景便签保持清晰完整。

### 7.2 身份选择

- 参与前选择“大人”或“小朋友”。
- 解释当前身份下“提问”和“回答”的去向。
- 记住最近一次身份，允许在“我的”中切换。
- 切换身份前必须确认，未提交草稿不得静默丢失。

### 7.3 提问

- 直接在便利贴书写区输入问题、设置公开化名或匿名并提交。
- MVP 建议问题长度为 5-80 个中文字符，配置项由后端控制。
- 自动显示目标身份。
- 提交后进入问题审核；通过后进入目标身份的问题池。
- 支持审核前撤回、审核后关闭回答。

### 7.4 回答

- 当前身份只看到可由自己回答的问题。
- 问题池默认按零回答和等待时间排序，并提供随机抽题，不提供内容分类筛选。
- 显示问题正文和已有回答数，不显示不必要的用户信息。
- MVP 建议回答长度为 1-160 个中文字符。
- 回答输入框直接位于完整便签书写区，输入内容同步呈现最终排版。

### 7.5 问题详情

- 展示问题及全部审核通过的回答。
- 支持回答排序、收藏、分享、举报。
- 当前身份符合目标身份时显示“我也来回答”。
- 未选择身份时点击回答，先进入身份选择，再返回原问题。

### 7.6 我的与通知

- 我的提问：审核中、待回答、已有回答、已关闭。
- 我的回答：审核中、已发布、被隐藏。
- 草稿：本地自动保存，正式版本与账号同步策略另行确定。
- 通知：审核结果、收到新回答、内容被精选或被处置。

### 7.7 运营后台

- 问题与回答分队列审核。
- 支持通过、拒绝、隐藏、恢复、精选、置顶和批量处理。
- 支持每日问题和预置内容管理。
- 支持查看两个方向的待回答库存、首次回答等待时间与举报队列。
- 支持紧急关闭投稿、只读模式和全站内容隐藏。

## 8. 内容生命周期

```text
问题草稿
  -> 问题审核中
  -> 待回答 / 审核拒绝 / 已撤回
  -> 收到回答

回答草稿
  -> 回答审核中
  -> 已发布 / 审核拒绝 / 已撤回
  -> 形成公开便签

公开内容
  -> 正常展示 / 被举报
  -> 隐藏 / 恢复 / 删除 / 归档
```

## 9. MVP 范围

### P0 必须具备

- 公共问答墙与游客浏览。
- 身份选择、记忆和切换。
- 四条身份/动作路径。
- 问题池、一题多答、详情页。
- 在便签中直接输入问题与回答，并保存草稿。
- 我的内容与基础通知。
- 审核、举报、隐藏、封禁与来源字段。
- 默认推荐流、近期已看去重与明确结束状态。
- 360-430px 手机视口优先，桌面端保持基础兼容。

### P1 运营增强

- 每日一问和运营精选。
- 收藏、分享图和个人问答册。
- 零回答问题召回与供需引导。
- 周报、内容运营看板和更细的通知策略。

### P2 表达扩展

- 家庭或班级私密空间。
- 手写、语音、图片回答及相应审核能力。
- 多语言支持。
- AI 风险预警和运营摘要，不替代人工回答或最终审核。

## 10. 指标

北极星指标：每周完成并通过审核的有效跨身份问答数。

关键指标：

- 问答墙独立访客及人均浏览卡片数。
- 浏览者转为提问者或回答者的比例。
- 两个方向的问题发布量与有效回答量。
- 问题 24 小时、7 天获答率。
- 首次有效回答的中位等待时间。
- 提问者查看回答的比例。
- D7/D30 回访率。
- 审核拒绝率、举报率、隐私信息拦截率和处置时长。

不以总发帖数、点赞数或儿童回答排名作为核心目标。

## 11. MVP 验收标准

- 游客可以不选择身份连续浏览全部公开内容。
- 四条路径的目标身份与问题池始终正确，前后端规则一致。
- 未审核问题不进入问题池，未审核回答不进入公开问答墙。
- 一个问题的多个回答能正确聚合，墙面卡片不会串题。
- 参与者刷新或返回后能找到自己的问题、回答与状态。
- 重复提交不会生成重复内容，失败后可以安全重试。
- 360-430px 主流手机宽度无文字遮挡、按钮溢出、底部导航遮挡或不可操作内容；桌面端无阻断性问题。
- 键盘可完成主要流程，动态状态有可访问提示。
- 官方与用户内容在前台不显示来源差异，后台能够查询与审计来源。
- 敏感信息提示、举报、隐藏与紧急只读开关均可用。

## 12. 研发前仍需拍板的决策

这些决策不阻塞低保真原型，但会影响正式技术方案：

1. 正式账号方式：微信授权、手机号、邀请码或监护人关联。
2. 身份切换限制及是否需要年龄分层。
3. 审核策略：全部先审、部分后审或不同路径差异审核。
4. 内容保留期限、用户删除权和运营导出规则。
5. 收藏和分享是否允许游客使用本地状态。
6. 正式品牌名、Logo、吉祥物和中文手写字体授权。
